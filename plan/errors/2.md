 Plan: Strip custom.js — React shell owns the chrome

 Context

 Chainlit is now embedded as an iframe inside the React shell's WorkspacePage. The React shell owns the preview iframe (:3000), the Publish button, and the branch badge (all
  in web/src/components/TopBar.tsx and WorkspacePage.tsx). orchestrator/public/custom.js was built to add those same UI elements directly to the Chainlit page — now they're
 duplicated and the custom.js chrome is redundant noise inside the iframe. Remove everything except what's needed for Chainlit to function.

 What to remove from custom.js

 Everything. The file currently adds:
 - Preview panel — right-side iframe for :3000, drag/resize handle, toggle button, refresh/open buttons, body padding. React WorkspacePage owns this.
 - Publish button — calls /api/git/publish. React TopBar owns this.
 - Branch badge — polls /api/git/status every 5 s. React TopBar owns this.
 - Layout management — adjusts body padding/grid to make room for preview panel. No longer needed inside an iframe.

 Result: custom.js becomes an empty file (or a one-line comment). Chainlit needs no custom JS to function as a chat surface.

 Architecture after this change

 docker compose up
   workspace     :3000 (Vite preview) + :4096 (OpenCode)  ← unchanged
   orchestrator  :8000 (Chainlit + FastAPI)                ← new service
   web           :5173 (built React shell via serve)       ← new service

 Browser opens http://localhost:5173
   → React fetches http://localhost:8000/api/*
   → Chainlit iframe src="http://localhost:8000"
   → Preview iframe src="http://localhost:3000"

 All three services share the project-data volume at /project so the orchestrator can run git directly instead of shelling into another container.

 Changes

 1. orchestrator/Dockerfile (new)

 FROM python:3.12-slim
 RUN apt-get update && apt-get install -y --no-install-recommends git && rm -rf /var/lib/apt/lists/*
 RUN pip install uv
 WORKDIR /app
 COPY pyproject.toml uv.lock ./
 RUN uv sync --frozen --no-dev
 COPY . .
 EXPOSE 8000
 CMD ["uv", "run", "chainlit", "run", "app.py", "--host", "0.0.0.0", "--port", "8000"]

 Prerequisite: run uv sync locally in orchestrator/ first so uv.lock includes aiosqlite. The Docker build uses --frozen so it won't mutate the lock file.

 Multi-stage: build with Node 20, serve the dist/ with npx serve.

 4. orchestrator/app.py — two fixes

 Fix A: CORS outermost. Move add_middleware(CORSMiddleware) to AFTER the @app.middleware decorators. Starlette inserts each registration at position 0; last-registered =
 outermost. Currently CORS is innermost and short-circuited responses from _lingua_git_middleware never get CORS headers.

 # After _lingua_git_middleware definition:
 fastapi_app.add_middleware(
     CORSMiddleware,
     allow_origins=["http://localhost:5173"],
     allow_methods=["*"],
     allow_headers=["*"],
 )

 Remove the add_middleware block from its current position (before the decorators).

 Fix B: Replace docker-exec git with direct git. Remove REPO_ROOT and COMPOSE_EXEC. Add PROJECT_DIR env var. Simplify _git() to run git with cwd=PROJECT_DIR directly:

 import os
 PROJECT_DIR = Path(os.getenv("PROJECT_DIR", "/project"))

 async def _git(cmd: str) -> tuple[int, str, str]:
     proc = await asyncio.create_subprocess_exec(
         "bash", "-c", cmd,
         cwd=str(PROJECT_DIR),
         stdout=asyncio.subprocess.PIPE,
         stderr=asyncio.subprocess.PIPE,
     )
     out, err = await proc.communicate()
     return proc.returncode or 0, out.decode().strip(), err.decode().strip()

 The existing git commands (git rev-parse --abbrev-ref HEAD, etc.) already work relative to cwd — no cd /project && prefix needed.

 5. orchestrator/opencode_client.py — configurable URL

 Change the default base_url to read from env:

 import os
 # line ~20, in __init__ or as module-level default:
 base_url: str = os.getenv("OPENCODE_URL", "http://localhost:4096")

 6. web/src/vite-env.d.ts (new, single line)

 TypeScript errors on import './styles/globals.css' because there's no type declaration for .css files. Standard Vite scaffold includes this file:

 /// <reference types="vite/client" />

 vite/client declares .css imports as string, silencing the TS2307 error.
